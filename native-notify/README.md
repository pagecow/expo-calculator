# Agent Notify — push setup for Expo Calculator

_Generated by Agent Notify (recipe v1, stack: React Native (Expo))._

This pull request adds the Native Notify device-registration client for your
stack. Push delivery (APNs for iOS, FCM for Android) is handled by Native
Notify — you do not use Expo's push service or run any push infrastructure.

> **Do not commit real credentials.** `NN_APP_ID` and `NN_APP_TOKEN` are read from the app's own configuration at build/run time.

## What is in this PR

- `native-notify/nativeNotifyClient.js` — a small, self-contained registration client.
- This guide.

## Steps to finish (the agent cannot do these for you)

1. **Get your app id + app token** from [Native Notify](https://dashboard.nativenotify.com)
   (**Keys** in the project's left sidebar — each value has a Copy button). Put them in
   your app's configuration:
   - They go in `app.config.js` (or `app.json`) → `extra: { nnAppId, nnAppToken }`, read with `Constants.expoConfig.extra`. The setup pull request writes the real values there — the app id and token live inside the app, so keep the repository private (rotate the token on the **Keys** page in [Native Notify](https://dashboard.nativenotify.com) if you ever want a fresh one).
2. **Get the device token** and call the registration function:
   - Request permission and get the token: `Notifications.getDevicePushTokenAsync()` (Expo) returns the APNs/FCM token directly.
   - Call `registerNativeNotifyDevice({ appId, appToken, platform, apnsToken | fcmToken })` whenever the token is granted or rotates.
   - Call `deregisterNativeNotifyDevice(...)` on sign-out if pushes should stop.
   - Show a push while the app is open: `expo-notifications` shows nothing until a notification handler is set, and on Android never hands it a push without a picture. `native-notify/nativeNotifyForeground.js` (the pull request adds it — see **Showing pushes while the app is open** below) sets the handler and shows such a push through an `expo-task-manager` task: run `npx expo install expo-task-manager`, then import it once at the top of your entry file, before `registerRootComponent`.
3. **Run the app and let it register**:
   - Expo Go cannot register a device — run a development build instead: `npx expo run:ios` / `npx expo run:android` (or an EAS development build).
   - The development build runs on an iOS Simulator (Xcode 14 or newer), an Android emulator with Google Play services, or a real phone — all receive push.
   - Allow notifications when the app asks.
4. **Send your first push:** click **Send push notification** in the setup guide's first-push card, or just
   ask Agent Notify (API: POST /api/universal/test-send). It is a REAL push
   notification — the banner arrives and it is saved in the notification inbox
   (**Push notifications → Inbox**, where you can delete any you do not want in
   users' inboxes). The transport result is immediate — accepted or failed with
   a plain-English reason.

## Showing pushes while the app is open

`expo-notifications` shows a push while the app is closed or in the background, but not while it is open: it shows nothing until a notification handler is set, and on Android a push without a picture is an FCM *data* message that it never hands to the handler.

The pull request adds `native-notify/nativeNotifyForeground.js`: it sets the notification handler and registers a task that expo-task-manager runs for every push, in every app state. While the app is open the task turns a push without a picture into a local notification; closed or in the background expo-notifications shows the push itself, so the task does nothing then.

1. In your terminal, run `npx expo install expo-notifications expo-task-manager` — the Android display needs `expo-task-manager`.
2. In `index.js`, add `import './native-notify/nativeNotifyForeground';` at the top, before `registerRootComponent` — it shows a push while the app is open. Your app starts through expo-router: create an `index.js` that imports it and then `expo-router/entry`, and point `main` in package.json at that file, so the task is defined before any screen loads.

Until the packages are installed, a check that analyzes every file reports the new file's imports as missing — nothing else is affected, because nothing imports it yet.


## Images in notifications

Fill in **Big picture** when you send from [Native Notify](https://dashboard.nativenotify.com), or set `bigPictureURL` in the API: an `https` JPEG or PNG under 1 MB.

**iPhone:** iOS never downloads a push's image by itself, so this pull request adds `targets/notification-service` — a notification service extension for the `@bacons/apple-targets` config plugin. It does nothing until you run `npx expo install @bacons/apple-targets` in your terminal (that also adds the plugin to your app config) and make a new iOS build (`npx expo prebuild -p ios --clean`, or a new EAS build).

**Android:** Firebase draws the picture while the app is closed or in the background, and `expo-notifications` shows it while the app is open once a notification handler is set — `native-notify/nativeNotifyForeground.js` sets one (see **Showing pushes while the app is open** above).

The iPhone Simulator never runs notification service extensions, so it shows the text without the picture — test images on an iPhone.

## Before your first push

- **iPhone:** an Apple Developer Program membership ($99 a year — a free Apple ID cannot create the push key) — [enroll](https://developer.apple.com/programs/enroll/); your app's Bundle ID registered with Apple with Push Notifications ticked — [Identifiers](https://developer.apple.com/account/resources/identifiers/list) → + → App IDs → App → Explicit Bundle ID (not a template value like `com.example.…`); the Push Notifications capability on the app target (the expo-notifications config plugin adds it when the native project is generated); then the Apple push key in [Native Notify](https://dashboard.nativenotify.com) (**Setup & docs → Push notifications setup → Connect Apple (iPhone)**).
- **Android:** a Firebase project with your Android app registered under its exact package name, `google-services.json` in the app module (`android/app/` — also set `android.googleServicesFile` in app.json), then the Firebase service-account key in [Native Notify](https://dashboard.nativenotify.com) (**Setup & docs → Push notifications setup → Connect Firebase (Android)**).

## Verify

The agent's verification loop sends a real push through the production
pipeline and reports the exact result. If it fails, the failure code maps to
a fix:

| Result | What it means |
| --- | --- |
| accepted | The device token is valid and credentials work end-to-end. |
| BadDeviceToken | Token is wrong / from the other APNs environment (debug vs release). |
| Unregistered | The app was uninstalled or the token was revoked — register again. |
| InvalidProviderToken | The APNs .p8 / key id / team id in Native Notify settings are wrong. |
| SENDER_ID_MISMATCH | The FCM service account does not match the app's Firebase project. |
